# Oleafly：Word 工作底板与 Agent 产品方案

2026-11-16。本页记录讨论及两位负责人独立源码审查后收束的设计方向，不代表全部已经实现；实际交付范围由[当前状态](agent/status.md)维护。

## 1. 产品要解决什么

核心是处理 Word 稿件：用户提供稿件、期刊模板和要求，系统与 Agent 完成格式处理、检查和研究辅助，用户围绕稿件查看结果、判断疑点并继续工作。普通编辑服务于这条主线；产品的价值在于减少用户理解规则、逐项操作和来回核对的负担。

Word 是主线，模板、规则、参考资料和成果围绕当前工作组织。PDF、图示和 HTML 等继续使用适合自己的渲染方式，保持交互能力，无须全部装进 A4。

## 2. 中栏是一张工作底板

| 区域 | 职责 |
| --- | --- |
| 左栏 | 稿件、模板、资料与项目导航，选择输入和发起操作。 |
| 中栏 | 实际稿件或当前成果；编辑、定位、查看修改、核对依据和批注。 |
| 右栏 | 既有 Agent：沟通、交办、追问和调整方向，与中栏共享当前上下文。 |

保留既有产品主题与整体结构，重做中栏交互，不把现成 Word 编辑器的整套界面直接嵌进来。

**同一底板、同一套操作界面。** 工作稿是主要操作对象；修改、批注、处理人和检查结果围绕相关内容按需展开。顶部只留材料身份、必要状态和主要动作。界面呈现可读要求与结果，XML、JSON 和校验摘要留在内部。

对象动作随正文选区、公式、图表等目标出现，不另占固定区域。点中明确对象可露出少量相关动作；普通拖选和键盘扩选只高亮，右键或键盘主动呼出浮条。位置跟随可见对象，操作绑定发起时的目标和版本。目标仍可见但放不下时，同一浮层临时靠到视口边缘；离屏即收起。浮层不进入正文流，露出动作也不收起反馈。用户明确打开对象面板时，反馈才让位，草稿仍保留。重新展开反馈时，收起对象工具。待审段落仅高亮并提供就地入口；流式内容、原文对照与处理按钮留在现有文档工具，不主动展开。已实现的操作见 [Word 编辑器文档](Editor.md#word-documents)。

点已有引文与插入新引文是两条路径。已有引文只在能解析出明确文献时显示「查看来源」；交叉引用跳到文内目标，不能当论文引文处理。在光标处主动唤起「插入引文」时，短浮层负责选文献并确认，整稿样式和书目刷新仍走文档级工具。能识别字段类型不等于能解析来源或安全写回，未知及第三方字段保留原样。图表同样只使用已确认的对象和来源关系，不按相邻文字猜题注或数据出处。新增写入须通过撤销、保存重开和 Microsoft Word 往返，再开放给用户。

插入只从前景工作稿的正文光标主动唤起。选择来源前锁定会话、段落、模型位置和文档修订。选择期间如果移动光标、切换材料或改了稿件，结束这次操作，不把引文改插到新位置。查找、取消或关闭时不改变纸面，不抢回用户已经移走的焦点。

默认开启的交互先按[候选发布包验收](../e2e/README.md#word-context-tools-release-candidate-check)检查。用长篇双栏稿和系统键鼠检查普通选字、跨页含引文复制，以及打开和关闭对象工具时纸面、滚动位置和稿件内容不变。随后将普通编辑后的稿件经 [Microsoft Word 另存并回导](../e2e/README.md#default-word-round-trip)，确认能继续编辑，正文手改、原有字段和分栏保留。引文写入另设开放条件，不阻塞默认路径验收。

开放引文写入前，用获准使用且包含可解析原生 Word 引文的真实长篇双栏稿副本完成以下验收，作者原件保持不变：

1. 在 Oleafly 桌面端分别于左右栏、跨页处主动打开浮层。用鼠标和键盘操作，确认普通选字与复制不唤起浮层，开关浮层不改变纸面或视口尺寸，也不引发意外滚动。用系统快捷键复制，另在文本编辑器中粘贴核对，包含引文的选区也要确认可见文字完整。
2. 在一处正文发起改写建议，在另一处继续编辑。确认待审入口不自动开栏或抢焦点；在窄窗用键盘打开对照、定位原段落并接受。撤销、重做时只有原段落的建议生效或撤回，另一处手改保留。另取一段发起改写后直接编辑目标，确认旧建议不能再接受。打开稿内已有引文、公式和有明确关系的图表动作，核对动作确实指向所选对象。
3. 选一个稿内尚未收录的 DOI，在左右栏各找一个正文段落，分别用裸 DOI 和 DOI 链接显式查询 Crossref 并确认插入。撤销第二处时，第一处和对应来源保留；撤销第一处时，新增的来源随引文一并移除。重做、保存并重开，确认正文编辑结果保留、两处都能查看正确来源，再导出副本。
4. 用 Microsoft Word 打开导出副本，确认没有修复提示、该 DOI 只对应一条当前文档来源。更新两处引文并重建书目，检查样式和来源没有重复；核对稿内原有的 Word 引文仍指向原文献。首次插入的显示文字只是缓存，不能作为样式生效的证据。
5. 把 Word 另存的副本重新导入 Oleafly，并用[引文往返检查](../e2e/README.md#word-citation-round-trip-acceptance)核对两份导出与原稿中的字段、书目、书签和分栏。文件检查不替代在 Word 中观察更新结果，也不替代回导后继续编辑。

**空间堆叠表现材料关系和查看状态。** 原稿与工作稿的身份沿真实纸张宽度上下叠放，后层露出纸边，点击即可换到前景；小眼睛选择查看方式。短过渡只移动身份和纸壳，正文可视矩形保持固定。工作会话持续存活，历史按需只读呈现，共用一套产品界面；不强制只有一个内核实例，也不通过反复加载不同版本破坏会话。原稿和工作稿不再各带一套完整界面交错共存。

关系须明确：原稿与修订稿是版本，模板是规则依据，论文是参考证据，数据与图是来源和产物。最初原稿、本次任务输入、当前工作稿、候选成果和已检查版本分别标识。定位跟随具体内容，不能以相同页码假定前后对应；无可靠映射时回开准确旧版。

## 3. 内核复用，产品界面自主设计

继续基于现有 EigenPal DOCX 内核二开，复用解析、排版、输入、选区、撤销和导出能力；按实际需求扩展格式读取与修改。使用内核提供的界面组合能力，按我们的工作流程设计操作入口。

系统解析模板及稿件的格式、样式继承、结构与文字，保留原始部件和来源，文字支持完整续读。分别报告内容已保留、可读、可写及检查覆盖范围，不能以原包完整保留推导全部可修改。工作中的大模型使用解析结果，理解说明文字、判断语义和安排处理；声明、观察格式与确定的期刊要求须区分。

随处理展示简短的依据摘要：采用哪个模板、哪些要求适用于哪些内容，以及冲突或未确定项。确定项连续执行，只将影响处理方向的疑点带给用户；模板里的示例格式不能自动成为全稿要求。

字体沿用既有设置、下载、缓存与会话刷新服务，按实际需要获取准确家族、字重和字形并记录版本。格式检查与视觉排版证据分开；视觉结果随字体或排版环境变化刷新或失效。期刊检查、预检、保存及导出复用已有服务。作者原件只读，处理作用于受管工作稿；产品内日常操作不依赖外部 Office 界面或 Computer Use。

## 4. Agent 能完成完整产品流程

**用户能完成的业务操作，Agent 在相同授权下也应能完成。** 人工按钮与 Agent 工具共用业务入口、文档状态、编辑事务、撤销和保存机制；已有注册与执行机制继续复用。

- **知道当前状态：** 正在查看的材料及选区、允许修改的工作稿、版本、未保存修改、所用模板、检查问题、任务与成果。
- **执行业务：** 导入和打开、读取模板、准备字体、编辑内容与格式、检查与预检、保存、导出、管理任务及调整产品设置。
- **展示结果：** 定位相关内容、展开问题或依据、打开成果、返回工作稿，让人看见实际处理对象。
- **返回事实：** 修改、保存和检查分别返回真实回执；模型总结不能替代执行结果。

**Agent 的操作实时呈现在产品里。** 左栏同步材料、任务进度、问题及成果状态；中栏随实际执行打开对象、定位内容、呈现修改与检查结果；右栏说明当前步骤。三栏由同一业务状态和执行回执驱动，不能用模型声称完成来提前改变状态。批量修改按编辑事务呈现，耗时操作显示真实阶段；完成、失败和待处理均有对应反馈。

默认跟随用户当前交办的任务，用户可随时暂停或恢复跟随。用户主动编辑、滚动或切换资料时保留其焦点与位置，后续执行继续更新数据并给出可点击提示，不强行切屏；后台及并行任务同步状态，只有被跟随的任务驱动中栏导航。跟随时让人看见操作对象、过程与结果，无须模拟鼠标移动或逐字输入。

查看对象与写入对象分开：浏览历史不自动改绑任务；从旧版指代“这里”时，只在目标映射可靠时修改工作稿，不能默默使用旧坐标操作隐藏稿件。

完整业务覆盖是长期要求，按实际任务核对人工、聊天、桌面 MCP 和研究任务入口的可用性、前置条件、对象与回执，复用现有注册，不以工具数量证明覆盖。新增功能同时提供人工与 Agent 入口、上下文和反馈。已授权的常规操作连续执行，不逐项审批。

## 5. 用户经历的完整流程

> 上传稿件与模板 → 交办“按模板处理” → 系统解析、Agent 安排并执行 → 在稿件上查看处理与剩余问题 → 继续修改、检查、保存或导出。

点击某项处理，应能定位内容，查看要求、依据、真实处理人及执行结果。已有修改前后值才显示“X → Y”；只有设置回执就显示“已设为 Y”。头像对应真实归属，无可靠位置的旧批注回开其留存版本。

| 实际发生的工作 | 对用户的呈现 |
| --- | --- |
| 直接修改当前 Word 会话 | 已应用，可继续编辑；按已有能力撤销、恢复或保存。 |
| 独立副本产生修改稿 | 待审阅成果，经既有冲突检查和应用入口进入工作稿。 |
| 产生报告、图、HTML 等 | 直接查看、回看来源并继续交办，无须统一经过“采纳稿件”。 |

任务完成、已应用、已保存、检查通过分别表达。撤销先沿共享时间顺序，不能承诺撤回某次任务而保留其后全部人工修改。资料往返保存准确版本、定位及阅读位置，支持从稿件到多份证据、成果后返回原处。

## 6. 当前基础与接下来的改动

已有 DOCX 内核、格式事实读取、部分 Agent 编辑工具、字体服务、保存恢复、版本留存、检查与批注任务链路。Word 已改为持久工作会话、单一可见纸面与共用产品工具栏，历史按需只读；当前查看身份与可写目标分开。Agent 全功能覆盖、通用格式差异和跨版本位置对应尚未完成。

本轮已接入真实操作回执、可暂停的跟随导航、当前材料上下文与资料往返保留。字体准备和导出复用人工入口，任务成果保留来源身份。原生材料验收与真实 IJAM 模板、中英文稿回归已通过，执行范围与本机证据见[当前状态](agent/status.md#中栏材料版本批注与成果回看2026-11-15)。使用内核组合接口优先于修改其生命周期，必要扩展在源码完成并验证。复用现有渲染器、服务和存储，不另建编辑器、评论库或 Agent 运行时。

**下面三条流程作为持续验收目标；本轮已验证指定八目标的真实整稿闭环及人工接管，任意稿件的处理质量和更广业务覆盖仍需另行验收：**

1. 上传含表格、页眉及中英文字体的稿件与模板，一次交办完成支持范围的处理、字体准备、保存、检查和导出，未覆盖项明确；不同 Agent 入口得到一致业务结果。执行时三栏同步真实进度与结果；暂停跟随后焦点和位置不被后续步骤抢走，恢复后能定位当前处理处。
2. 手改后发任务，再看任务输入与结果，能找回对应内容；交错编辑后按真实顺序撤销，未保存内容与工作会话仍在，过期检查不冒充当前结果。
3. 从稿件打开 PDF 证据、再看交互 HTML 成果，返回原位置继续工作；查看旧版时，Agent 的实际修改目标始终明确。

先贯通这些流程，再扩大业务覆盖与差异能力；不等待全类型语义差异或选择性任务撤销才交付。功能与测试通过不等于已经证明 Word/WPS 分页一致。
