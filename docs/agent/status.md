# Oleafly Agent：当前状态与实施计划

核对日期：2026-11-10。范围：Oleafly 的普通 Agent、ResearchTask、任务群及应用接入。
本文维护当前能力、交付状态和剩余工作；[架构](architecture.md)维护工作合同，
[复用依据](reuse.md)维护固定版本的组件选择。Workbench 领域实现与验收由
[S1 状态页](../../services/research-workbench/docs/s1-progress.md)维护。

## 目标与边界

- 单 Agent 和任务群都应连续使用 Oleafly 的编辑、编译、PDF、文献、期刊、项目和实验能力，
  从用户正在处理的对象出发，把结果交回可检查、可接管的界面。
- 保留现有期刊研究、来源审阅、规则与检查，以及 LaTeX、PDF、文献和人工工作方式。
  任务群增加一种工作组织方式，不替代这些功能或普通 Agent。
- 成员共享目标、过程、版本、运行和结果，各有上下文；可以互问、质疑、执行和探索。
  用户能跨时间标注旧决定，今天的明确叮嘱按意图优先进入相关工作。
- 标注可包含情绪、评价、反例、遗漏规则和能力改进要求；原话、当前处理、持续要求与长期提炼分开。
- 运行时负责投递、等待、版本和恢复；模型负责理解与判断。能力按需提供，避免把全部规则常驻提示词。
- 完整期刊投稿流程和综合投稿验收不在本线范围；已有期刊能力仍在范围内。
  部署、发布及用户数据迁移按具体任务授权执行。

## 思路演进

| 从哪里转向哪里 | 保留下来的判断 |
| --- | --- |
| 小模型军团 → 按问题组合能力 | 检索、抽取、窄核验和复杂推理按实测能力分工，角色不等于模型大小。 |
| 更多提示词 → 动态能力与观测 | 区分配置、提供、请求、执行和实际采用；提供过不证明使用正确。 |
| 临时 helper → 持续成员 | 共享过程、独立上下文、直接交流及相关变化后的接续。 |
| 通信与审查 → 深入使用应用 | 研究推进、开放探索和实际业务操作都要有可检查的结果。 |
| 当前聊天 → 跨时间反馈 | 旧对象上的新叮嘱仍影响当前相关工作，处理结束不自动撤销持续要求。 |

### 本轮文献工作流与协作对照

同一教学稿预置三条错误或过度陈述，输入两篇真实论文；任务要求查实际正文、修任务副本、提出下一实验、
编译并核对新 PDF，保留原项目和两条 bibliography。每个初始任务的工作时间额度为 12 分钟，
既有收尾阶段可继续消耗时间。前三项使用同一 Trae DeepSeek/high；后两项使用 Sol/high 协调者和
Trae/high 审查者。未设置匹配的 token 额度，每种只运行一次，属于能力探针。

| 样例 | 实际活跃分钟（含收尾） | provider 报告输入 / 输出 token | 结果 |
| --- | ---: | ---: | --- |
| 单 Agent | 5.07 | 1,799,305 / 39,781 | 三条核心陈述修正，保留了单位和实验判据等问题。 |
| 一个阅读 helper | 5.72 | 1,706,323 / 51,066 | helper 读源且意见被采用；仍把计算复杂度误写为同阶内存复杂度。 |
| 旧群调度（全 Trae） | 14.41 | 4,266,865 / 69,446 | 独立审查补出多项遗漏；触发时间预算停止，最终实验仍混淆分块 baseline 与整段 dense attention。 |
| 旧群调度（Sol＋Trae） | 13.68 | 890,383 / 36,714 | 正文及实验更连贯，仍触发时间预算停止。保留的旧 PDF 不能一概当作后续源码的最终产物。 |
| 首次加入批次交接（Sol＋Trae） | 10.72 | 2,038,837 / 40,545 | 六次成员执行，未触发预算停止；一份新 PDF 的全文实际回读，三条陈述修正且 bibliography 保持原字节。 |

交接样例中，Trae 先核查来源并提出修正，Sol 再修改、编译与读 PDF。Trae 曾把 Table 10 的 full-attention
行误读成 sparse-attention 比较，Sol 查源指出，Trae 随后明确撤回；最终正文保留了正确解释。
下一实验包含长度、初始化、资源与准确率判据，明确标为未运行。独立复核未在该最终稿发现同等级的
事实或实验自相矛盾，但两篇论文和单个 IMDB 方案不能证明广泛研究质量。

这次交接减少了先写完再等同事的阻塞，却仍出现研究记录变化后的重复介入；其输入 token 高于旧混合模型
样例，因此不能宣称节省 token、费用或普遍优于单 Agent。首次真实交接运行后发现的嵌套等待和进度回复
吞最终答复问题另经定向回归修复，不能追认为首次运行时已具备。

随后在原决定下提交不点名的明确反例，恢复到第 2 代，沿用累计工作时间，再增加 10 分钟工作额度；
这段续作单独记账，不改写上表。协调者查回原论文关于 global-token 数量独立于序列长度的条件，
修正文稿、增加随长度变化的 global-mask 实验，编译并读取新 PDF 全文及两页图像，
再以实际源码/PDF 引用处理原标注，二次提炼一条持续要求。原项目与 bibliography 原字节不变，
第 1 代保留原文仍可精确回读；打包界面的处理结果能打开第 2 代 PDF 并提取对应文字。

该续作用了 12.31 个活跃分钟（含既有收尾阶段），最终触发 `budget_time`。
正文变化正确唤醒 Evidence，但随后双方更新同一 handoff 又制造下一轮工作。
当前源码已仅对任务自身 handoff/plan 取消隐式读写唤醒，保留事件、显式订阅、用户请求和其他证据变化；
12 项关注路由与 5 项调度回归通过。最新打包应用的脚本 provider 流程完成 5 次执行，
保留 6 条协调文件事件、未由这些事件唤醒成员，正文变化仍使未点名的读者介入，最终无预算停止。
该流程验证运行时收敛，不代替修复后的真实模型收益对照，也不追认为失败运行时已具备。
独立内容复核还指出实验未明确定义窗口总宽与半径，短序列对照有歧义；该问题保留为样例残留，
没有修改冻结产物冒充模型完成。此实验仍未执行。

本轮本机验证包括 ResearchTask 库 652 项（在末次新增回归前）、随后 23 项协作和上述 12/5 项定向回归、
16 项 paper 窗口与缓存、14 项 Agent suspend、56 项桌面任务检查，以及受影响前端 147 项用例。
最新打包应用另通过 PDF 历史选段和期刊历史标注两条原生流程，使用脚本 provider 与隔离数据。
类型、语言目录、Skill pack、相关 Clippy 与构建通过。debug 原生链接仍报告 unwind 表大小警告，
未据此声称 release 性能；本轮未重复全仓测试。

本机原始依据位于忽略目录 `.private/research-workflow-eval/`，包括预先登记的任务条件、原生应用数据、
实际模型事件、初始产物、原项目比对、合成历史界面及必要的构建/失败日志；这些本地材料不随干净 checkout
提供，不构成公开可复现 benchmark。当前费用未知。正式安装版与 Windows 服务未更新。

## 剩余工作与推进顺序

1. 依据这次对照定位重复介入的实际成因，先验证消息、依据变化和未决工作是否有新增信息；
   再扩大匹配能力与总预算的样本，比较有效发现、澄清、探索、用户负担和真实用量。
2. 按实际场景继续贯通文献、引用和其他应用入口，沿“当前对象 → 来源 → 业务操作 →
   结果核查 → 原对象回链 → 界面接管”验收，不只验证能读取文件。
3. 从实际关联扩展语义职责候选、遗漏规则吸收、一次指定模型及有依据的能力改进，
   保留来源和候选身份，不把情绪或附和变成事实。
4. 外部 ACP/CLI 执行端出现已复现的投递或副作用缺口时，再借用相应 receipt/fencing 合同；
   不重复引入现有 TaskStore 已有的本地队列和恢复。
5. Windows 小模型仅替换有明确输入输出和对照的窄环节。此前小样本标定及部署记录是历史材料，
   当前服务状态和“能补主 Agent 漏项”的收益均未由本线确认。
6. 跨任务记忆作为可选来源候选与检索辅助，按实际缺口验证；不接管当前状态，
   也不把历史建议升级成用户要求或已验证事实。

后续改动更新本页相关正文；技术合同改[架构](architecture.md)，组件选择改[复用依据](reuse.md)。
普通迭代不新增综合报告；重要运行保留能支撑结论的原始依据，摘要引用该依据。
