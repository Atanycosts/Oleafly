# Oleafly Agent：当前状态与实施计划

核对日期：2026-11-09。范围：Oleafly 的普通 Agent、ResearchTask、任务群及应用接入。
本文维护当前能力、交付状态和剩余工作；[架构](architecture.md)维护工作合同，
[复用依据](reuse.md)维护固定版本的组件选择。Workbench 领域实现与验收由
[S1 状态页](../../services/research-workbench/docs/s1-progress.md)维护。

## 目标与边界

- 单 Agent 和任务群都应连续使用 Oleafly 的编辑、编译、PDF、文献、期刊、项目和实验能力，
  从用户正在处理的对象出发，把结果交回可检查、可接管的界面。
- 保留现有期刊研究、来源审阅、规则与检查，以及 LaTeX、PDF、文献和人工工作方式。
  任务群增加一种工作组织方式，不替代这些功能或普通 Agent。
- 成员共享目标、过程、版本、运行和结果，各有上下文；可以互问、质疑、执行和探索。
  用户能跨时间标注旧决定，今天的明确叮嘱按意图优先进入相关工作。
- 标注可包含情绪、评价、反例、遗漏规则和能力改进要求；原话、当前处理、持续要求与长期提炼分开。
- 运行时负责投递、等待、版本和恢复；模型负责理解与判断。能力按需提供，避免把全部规则常驻提示词。
- 完整期刊投稿流程和综合投稿验收不在本线范围；已有期刊能力仍在范围内。
  部署、发布及用户数据迁移按具体任务授权执行。

## 思路演进

| 从哪里转向哪里 | 保留下来的判断 |
| --- | --- |
| 小模型军团 → 按问题组合能力 | 检索、抽取、窄核验和复杂推理按实测能力分工，角色不等于模型大小。 |
| 更多提示词 → 动态能力与观测 | 区分配置、提供、请求、执行和实际采用；提供过不证明使用正确。 |
| 临时 helper → 持续成员 | 共享过程、独立上下文、直接交流及相关变化后的接续。 |
| 通信与审查 → 深入使用应用 | 研究推进、开放探索和实际业务操作都要有可检查的结果。 |
| 当前聊天 → 跨时间反馈 | 旧对象上的新叮嘱仍影响当前相关工作，处理结束不自动撤销持续要求。 |

## 当前能力

以下实现已经合入 fork；运行依据是此前保留的验收，不表示本次文档整理重新运行了产品。

| 能力 | 已实现的范围 | 仍有边界 |
| --- | --- | --- |
| 单 Agent 应用操作 | 冻结编辑器缓冲、选区、执行端及任务输入；修改任务副本、编译、读取实际 PDF 图文并预览。 | 尚未完成所有文献、引文及其他应用入口的贯通。 |
| 持久任务群 | 成员身份、独立会话/执行/用量、消息、逐成员工作、关注、共享预算与恢复。 | 同群串行执行；不宣称并行多写或任意外部执行端均支持。 |
| 相关变化后介入 | 显式订阅，以及成功受管读写和标注处理形成的对象关联；工作保留触发原因。 | helper、shell、MCP 和外部写入尚不统一归因；语义职责传播待扩展。 |
| 历史标注 | 普通聊天、ResearchTask 与内置成员共用原话、handling、distillation 和持续要求。 | 任意 `@模型`的一轮指定执行、遗漏规则吸收及自动能力调整待实现。 |
| ACP 接续 | 启动各路径提供当前结构化标注；prepared 与完整 prompt 帧 flush 后的 delivered 分开。 | 回执只到本地传输；持续 ACP 任务群和运行中轮内标注未接。 |
| 动态上下文 | 精简技能目录、逐轮 schemas、工具发现、按需技能加载、摘要和精确回读。 | 字节缩减不直接证明 token 或费用降低。群快照仍全量返回事件；执行历史仅取最近 100 条，超界来源不可用，尚待分页优化。 |
| 文件与 helper 来源 | 受管 `read_file` 留存精确字节、hash 和调用归属；最终 ToolOutcome 决定成功来源；helper 累计用量汇总。 | 其他 helper 工具活动和独立费用明细未采集；外部直接读取不在同一覆盖中。 |
| PDF 历史选段 | 原件、当时选段、当前源码和新产物分开；输入初始化阻塞执行；处理结果可回到原页。 | 正常打包流程及恢复已有验收，取消/删除交错由 store/命令回归覆盖，未做完整原生 UI 时序验收。 |
| 期刊原生接续 | context/read/check 复用领域服务；任务绑定领域输入；明确记录类型的重扫、回执、订阅和重启补接。 | 不等于全领域事件日志，不把 DOCX 检查推广为 LaTeX 检查；CLI daemon 无原生期刊工具。 |
| Finding 与处置 | 数字检查保留规则与输入版本，人工处置和当前有效性分开。 | 尚未成为涵盖代码、引用与所有领域的一套通用检查器。 |

## 剩余工作与推进顺序

1. 以匹配的能力和总预算比较单 Agent、helper 与任务群，核对有效发现、澄清、探索路线、
   重复唤醒、用户处理负担和真实用量；当前三成员样例不能直接当作节省或质量优势。
2. 按实际场景继续贯通文献、引用和其他应用入口，沿“当前对象 → 来源 → 业务操作 →
   结果核查 → 原对象回链 → 界面接管”验收，不只验证能读取文件。
3. 从实际关联扩展语义职责候选、遗漏规则吸收、一次指定模型及有依据的能力改进，
   保留来源和候选身份，不把情绪或附和变成事实。
4. 外部 ACP/CLI 执行端出现已复现的投递或副作用缺口时，再借用相应 receipt/fencing 合同；
   不重复引入现有 TaskStore 已有的本地队列和恢复。
5. Windows 小模型仅替换有明确输入输出和对照的窄环节。此前小样本标定及部署记录是历史材料，
   当前服务状态和“能补主 Agent 漏项”的收益均未由本线确认。
6. 跨任务记忆作为可选来源候选与检索辅助，按实际缺口验证；不接管当前状态，
   也不把历史建议升级成用户要求或已验证事实。
